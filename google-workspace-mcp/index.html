Google Workspace MCP: connect and disconnect

  • One Google key for Claude Code on your computer and your OpenClaw agent on the server
  • Three free pages on GitHub and publishing the app, so the sign-in doesn’t expire every 7 days

  • Ready prompts: copy, paste into Claude Code, follow

How it fits together
Google Workspace MCP gives an AI tool access to your Gmail, Calendar, Drive, Docs and Sheets. You create one key in Google Cloud, sign in once on your computer, and then copy that sign-in to the server. The server has no browser, so it can’t sign in by itself.
StepWhere

2. Three pagesGitHub, free

4. Claude CodeYour computer, prompt B

💡
Do the steps in this order. Steps 1–3 are done once. Step 5 reuses the sign-in from step 4.
01
Google Cloud: create the key
Sign in to Google with the account you want to connect, then open each link below in the same browser.
Create a new project
Open Create a project. Any name, for example “my-assistant”. Press Create and make sure the new project is selected at the top of the page.
Enable 10 APIs
Open each link and press Enable: Gmail, Calendar, Drive, Docs, Sheets, Slides, Forms, Tasks, People, Apps Script.
Turn on the Apps Script API for your account
One switch in Apps Script settings: Google Apps Script API → On.
Start Google Auth Platform
Open Google Auth Platform and press Get started. App name: anything. User support email: your Gmail. Audience: External. Contact email: your Gmail.
Add yourself as a test user
Open Audience → Test users → Add users → your Gmail → Save.
Create the key file
Open Clients → Create client → Application type: Desktop app → Create → Download JSON. Rename the file to client_secret.json and keep it in its own folder outside your projects, for example Documents/google-mcp.
⚠️
This file is a key. Don’t send it in a chat, don’t put it in GitHub and don’t keep it inside a project folder.
02
Three free pages on GitHub
Google now asks for a home page, a privacy policy and terms of service before it lets you publish the app. Until they are filled in Branding, the Publish app button stays grey. You can host all three pages for free on GitHub Pages. Your site address will be USER.github.io, where USER is your GitHub username.
Way 1, quick: Claude Code makes the site for you. Your GitHub must be connected to Claude Code.
Prompt A · GitHub Pages for branding
Create my GitHub Pages site for Google OAuth branding. My GitHub is already connected to you (gh CLI or GitHub MCP). 1. Find my GitHub username. Below it is USER. Ask me which email to show as the contact. 2. If the repo USER.github.io does not exist, create it as public. Add three short pages in English: - index.html: a personal assistant app that connects my own Google account to my AI tools; not a commercial service. - privacy.html: the app accesses only my own Google data, at my request; data is processed by the AI tools I use (such as Anthropic Claude) on my behalf; nothing is sold or shared with third parties; contact email. - terms.html: personal, non-commercial use only, provided as is, no warranty. If the repo already exists, only add the missing pages and do not delete anything. 3. Make sure GitHub Pages is enabled from the main branch. 4. Check the three URLs every 30 seconds until all of them open (status 200), at most 10 minutes. 5. Give me exactly these four lines to paste into Google Auth Platform, Branding: Application home page: https://USER.github.io/ Application privacy policy link: https://USER.github.io/privacy.html Application terms of service link: https://USER.github.io/terms.html Authorized domain: USER.github.io
Way 2, by hand in the browser: about 10 minutes.
Sign in to GitHub and find your username
Open github.com. Your username is shown when you click your avatar in the top right corner. Below it is USER.
Create the repository USER.github.io
Open New repository. Repository name: exactly USER.github.io, for example anna-smith.github.io. Choose Public, tick Add a README, press Create repository.
Add three files
In the new repository press Add file → Create new file. Name: index.html. Paste the template below and replace YOUR-EMAIL. Press Commit changes. Do the same for privacy.html and terms.html.
Template · index.html
<!doctype html> <html lang="en"> <head><meta charset="utf-8"><title>My Assistant</title></head> <body> <h1>My Assistant</h1> <p>A personal assistant app that connects my own Google account to my AI tools. It is not a commercial service.</p> <p><a href="privacy.html">Privacy policy</a> | <a href="terms.html">Terms of service</a></p> <p>Contact: YOUR-EMAIL</p> </body> </html>

<!doctype html> <html lang="en"> <head><meta charset="utf-8"><title>Privacy policy</title></head> <body> <h1>Privacy policy</h1> <p>My Assistant accesses only my own Google data, and only at my request.</p> <p>The data is processed by the AI tools I use, such as Anthropic Claude, on my behalf.</p> <p>Nothing is sold or shared with third parties.</p> <p>Contact: YOUR-EMAIL</p> </body> </html>

<!doctype html> <html lang="en"> <head><meta charset="utf-8"><title>Terms of service</title></head> <body> <h1>Terms of service</h1> <p>My Assistant is for personal, non-commercial use only.</p> <p>It is provided as is, without any warranty.</p> <p>Contact: YOUR-EMAIL</p> </body> </html>
Check that GitHub Pages is on
In the repository open Settings → Pages. Source: Deploy from a branch. Branch: main, folder / (root). Press Save if you changed anything.
Open the three pages
Wait 1–10 minutes, then open https://USER.github.io/, https://USER.github.io/privacy.html and https://USER.github.io/terms.html. All three must open. Progress is visible in the Actions tab of the repository.
💡
Use the same app name on the home page and in Branding. In the templates it is “My Assistant”.
03
Branding and publishing
While the app is in Testing, Google ends your sign-in every 7 days and the agent loses your mail. In Production the sign-in stays.
Fill in Branding and press Save
Open Branding and fill in the fields from the table.
Branding fieldWhat to enter
App nameThe name from your home page, for example My Assistant
User support emailYour Gmail
App logoLeave empty
Application home pagehttps://USER.github.io/
Application privacy policy linkhttps://USER.github.io/privacy.html
Application terms of service linkhttps://USER.github.io/terms.html
Authorized domainsAdd domain → USER.github.io, without https:// and without a slash at the end
Developer contact informationYour Gmail
🚫
Don’t upload a logo. Google says it right on the page: once there’s a logo, the app must pass verification before it can leave Testing.
💡
“Your branding is not being shown” or “Branding verification issues”. Press Cancel. This only affects how the app name looks on the sign-in screen. Everything still works.
Publish the app
Open Audience → Publish app → Confirm. The status changes to “In production”. “0 users / 100 user cap” is normal.
Sign in to Google again
Only if you already signed in while the app was in Testing: that old sign-in still ends after 7 days. Ask Claude Code: “Delete my Google sign-in in ~/.google_workspace_mcp/credentials and sign me in again.” Then run prompt C once more to copy the new sign-in to the server.
✅
The screen “Google hasn’t verified this app” stays after publishing. That is normal for a personal app: Google’s verification is only for services with outside users.
04
Connect to Claude Code
Paste the prompt into Claude Code on your computer. Replace the text in angle brackets with your path to client_secret.json.
Prompt B · Claude Code
Connect Google Workspace MCP to Claude Code globally (user scope), so it works in every session. Server: https://github.com/taylorwilsdon/google_workspace_mcp 1. Install uv if it is missing (https://docs.astral.sh/uv/). 2. Clone the repo to ~/.local/share/google_workspace_mcp (on Windows: %USERPROFILE%\.local\share\google_workspace_mcp) and run uv sync there. 3. My OAuth key file is here: <paste the full path to client_secret.json>. Never print its contents. 4. Add the server with claude mcp add (check claude mcp add --help for the exact syntax): - name: google-workspace, scope: user, transport: stdio - command: uv run --directory <repo path> main.py --tool-tier complete - env: GOOGLE_CLIENT_SECRET_PATH=<path to client_secret.json>, OAUTHLIB_INSECURE_TRANSPORT=1 5. Run claude mcp list and confirm google-workspace is connected. Then tell me to restart Claude Code and ask "show my last 3 emails" to sign in with Google.
🔁
Restart Claude Code after the install. Close it completely and open it again. Until then the Google tools don’t appear, and Claude will say it has no access to your mail.
Claude Code restarted
Signed in with Google
Ask “show my last 3 emails” and open the link. On “Google hasn’t verified this app” press Advanced → Go to your app name. Allow everything on the next screen.
Claude Code shows your last 3 emails
05
Connect to OpenClaw on the server
This prompt copies your key and sign-in from the computer to the server and adds Google to your main agent. Replace <my Gmail> in two places.
Prompt C · OpenClaw on the server
Connect Google Workspace MCP to my OpenClaw main agent on my server. Use the openclaw-docs skill; don't invent commands or flags. The server has no browser for Google sign-in, so reuse the sign-in I already did on this computer via Claude Code. 1. On this computer, find client_secret.json (path in the google-workspace entry of my Claude Code config, GOOGLE_CLIENT_SECRET_PATH) and the folder ~/.google_workspace_mcp/credentials (Windows: %USERPROFILE%\.google_workspace_mcp\credentials). It must contain <my Gmail>.json; if not, stop and tell me to sign in via Claude Code first. Never print these files. 2. ssh to my server. Install uv if missing. Clone https://github.com/taylorwilsdon/google_workspace_mcp to /root/.local/share/google_workspace_mcp and run uv sync there. 3. Copy client_secret.json to /root/.google_workspace_mcp/client_secret.json and the credentials folder to /root/.google_workspace_mcp/credentials. Permissions: folders 700, files 600. 4. Save the server in OpenClaw with openclaw mcp set GoogleWorkspace and this JSON (use the real path to uv from `command -v uv`): {"command":"/root/.local/bin/uv","args":["run","--directory","/root/.local/share/google_workspace_mcp","main.py","--single-user","--tools","docs","sheets","slides","forms","appscript","calendar","gmail","drive"],"env":{"GOOGLE_CLIENT_SECRET_PATH":"/root/.google_workspace_mcp/client_secret.json","WORKSPACE_MCP_CREDENTIALS_DIR":"/root/.google_workspace_mcp/credentials","OAUTHLIB_INSECURE_TRANSPORT":"1","HOME":"/root","WORKSPACE_MCP_PORT":"8000","MCP_SINGLE_USER_MODE":"1","USER_GOOGLE_EMAIL":"<my Gmail>"},"connectionTimeoutMs":120000} 5. Run openclaw mcp doctor --probe and confirm GoogleWorkspace connects and lists tools. If the docs say the Gateway needs a restart to pick it up, restart it. 6. Tell me to ask my agent in Telegram: "show my last 3 emails". Never show tokens or keys in the chat. Don't open any ports.
💡
The agent may go quiet for a minute. OpenClaw saves and tests MCP servers only while the Gateway is stopped, so Claude Code stops it and starts it again. Drive is in the list on purpose: the nightly server backup uploads to it.
The check shows GoogleWorkspace connected with a list of tools
The agent shows your last 3 emails in Telegram
06
Disconnect or switch accounts
Signed in with the wrong account, or want to remove access? The access lives in four places. Close all four.
WhereWhat to do
1. Claude CodeRemove the server and delete the sign-in files on your computer
2. OpenClawRemove the server from the agent and delete the sign-in files on the server
3. Your Google accountRemove the app’s access, so old sign-ins stop working everywhere
4. Google CloudDelete the key or the whole project. Only if you won’t connect again
Places 1 and 2 are covered by one prompt.
Prompt D · disconnect
Disconnect Google Workspace MCP from Claude Code on this computer and from my OpenClaw agent on my server. For OpenClaw use the openclaw-docs skill; don't invent commands. Show me the plan first and wait for my OK. Never print the contents of token or key files. On this computer: 1. Remove the server: claude mcp remove google-workspace -s user. Confirm with claude mcp list. 2. Delete the sign-in files in ~/.google_workspace_mcp/credentials (Windows: %USERPROFILE%\.google_workspace_mcp\credentials). Keep client_secret.json unless I ask for a full cleanup. On the server (ssh): 3. OpenClaw changes MCP servers only while the Gateway is stopped: run openclaw gateway stop, then openclaw mcp unset GoogleWorkspace, then openclaw gateway start. 4. Delete /root/.google_workspace_mcp/credentials. For a full cleanup also delete /root/.google_workspace_mcp/client_secret.json and /root/.local/share/google_workspace_mcp. 5. Check: openclaw mcp list no longer shows GoogleWorkspace, openclaw gateway status is healthy, and my agent still answers in Telegram. If my nightly backup uploads to Google Drive with this sign-in, warn me: it will stop working until I connect Google again. At the end remind me to remove the app's access at https://myaccount.google.com/permissions.
Claude Code and OpenClaw no longer list Google tools
App access removed in your Google account
Open myaccount.google.com/permissions, find your app name, remove all access. Do it in the account that was connected by mistake.
Optional: client or project deleted in Google Cloud
Only the key: open Clients, click your client → Delete. The whole project: open Project settings → Shut down, type the project ID → Shut down. Google deletes it for good after 30 days. Skip this if you plan to connect again.
🔄
Switching to another account. Run prompt D, remove access in the wrong account, then in Claude Code ask “show my last 3 emails” and sign in with the right account. After that run prompt C again with the new Gmail. If the app is still in Testing, first add the new Gmail in Audience → Test users.
07
Safety
The sign-in files open your mail. Anyone who has client_secret.json and the credentials folder can read your Gmail. Never put them in a chat, in GitHub or in a screenshot.
An agent with mail is the “lethal trifecta”. It reads your private data, reads emails from strangers and can send messages out. One email with hidden instructions is enough to trick it. That’s why the agent sends, forwards and deletes only after your “OK”.
