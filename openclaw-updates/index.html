How the alerts work
OpenClaw already checks for a new version once a day, but it shows the result only in the console. We add a small daily job: the main agent looks at that result and writes to you in Telegram only when there’s something new.
WhoDoes what
The agentChecks every day, tells you the new version, your version and what changed
YouDecide when to update and run the safe-update prompt
⚠️
The agent never updates by itself. An update restarts the Gateway, and the agent goes offline for a few minutes. Do it when you have time to check the result, after a fresh backup.
01
Set up the alerts
Paste the prompt into Claude Code on your computer. It connects to the server and creates the daily job.
Prompt A · daily update alert
Set up daily OpenClaw update alerts from my main agent on my server. Use the openclaw-docs skill; don't invent commands or flags. Show me the plan and wait for my OK. Never show tokens in the chat. Goal: once a day my main agent checks for a new OpenClaw version. If there is one, it messages me in Telegram: the new version, my current version and 3-5 short points about what changed (from https://docs.openclaw.ai/releases). If nothing is new, it stays silent. It never updates or restarts anything by itself. 1. ssh to my server. Show openclaw --version and openclaw update status. Check that automatic updates are off (update.auto.enabled). If they are on, tell me and ask before changing anything. 2. Create a recurring automation for the main agent with openclaw automations create (check openclaw automations --help first): every day at 10:00 in my time zone (ask me which), isolated session, delivered to me in Telegram as the owner (--announce --channel telegram --delivery-target owner). If owner delivery isn't set up, use --to with my Telegram ID. 3. The job's instruction for the agent: run openclaw update status --json. If no newer version is available, reply NO_REPLY. If there is one, send the message described above and end it with "To update, run the safe-update prompt in Claude Code." Never run openclaw update. 4. If the agent can't run that command inside the job, tell me why and suggest the simplest fix from the docs. 5. Run the job once now and show me the result and the run history.
Automatic updates are off

Update safely when the alert comes
StepWhy
1. BackupA verified copy of the agent is your way back if the update breaks something

Prompt B · safe update
Update OpenClaw on my server safely. Use the openclaw-docs skill; don't invent commands. If anything fails, stop and ask me. 1. ssh to my server. Show openclaw --version and openclaw update status. 2. Backup first: openclaw backup create --output ~/Backups/openclaw --verify (create the folder with mode 700 if needed). Confirm the archive is verified. If my nightly server backup exists, check that last night's run succeeded. 3. Preview: openclaw update --dry-run. Tell me in plain words what will change and wait for my OK. 4. Update: openclaw update. 5. Check: openclaw --version, openclaw doctor, openclaw gateway status, openclaw health, openclaw mcp doctor --probe. Then tell me to send my agent a test message in Telegram. 6. If something broke, show me the error and follow the update troubleshooting page in the docs. Don't improvise fixes. The backup from step 2 is the way back.

03
Disconnect the agent from ChatGPT
Your agent uses your ChatGPT subscription as its model. The server keeps a saved sign-in to your ChatGPT account. Remove it and the agent has no model.
🚨
Without a model the agent stops answering. The ready-made bots from the course use the same subscription through the Gateway, so they stop too. If you only want another account, switch instead of disconnecting.
Prompt C · disconnect or switch ChatGPT
Disconnect my OpenClaw agent on my server from my ChatGPT subscription, or switch it to another ChatGPT account (I'll say which). Use the openclaw-docs skill; don't invent commands. Show me the plan and wait for my OK. Never print tokens. 1. ssh to my server. Run openclaw models auth list --provider openai and show me the saved profiles: ids and accounts only. Tell me which agents and bots use them. 2. Warn me what stops working without this subscription and whether another model provider is set up as a fallback. 3. To disconnect: openclaw models auth logout <profileId> --yes for each profile I choose. 4. To switch accounts: openclaw models auth login --provider openai --device-code --force. Give me the link and the code from the output; I'll approve it in my browser with the right ChatGPT account. 5. Check in the docs whether the Gateway must be stopped for these commands, and stop and start it if needed. Then show openclaw models auth list --provider openai and openclaw gateway status, and tell me to send my agent a test message.
On the OpenAI side. If you think the server was hacked, or you connected the wrong account: open ChatGPT → Settings → Security. Remove OpenClaw from connected apps if it’s listed, press “Log out of all devices”, then change the ChatGPT password.
